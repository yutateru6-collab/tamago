# 設計

依存関係は UI → application → domain / platform。domain は React、DOM、ストレージ、OSに依存しない。

| 層 | 責務 |
|---|---|
| src/domain | World型、調整値、決定的な状態遷移、制作・探索ルール |
| src/platform/activity.ts | 計測情報の境界。現在は明示的なデモ入力のみ |
| src/platform/storage.ts | バージョン検証、保存、競合検出 |
| src/application/useWorld.ts | 読込→変更→保存→UI反映。Web Locksで同一originの更新を直列化 |
| src/ui | 表示。計測や報酬計算をしない |
| src/Prototype.tsx | ナビゲーションと帰還・試作シート |

## オフライン進行

常時バックグラウンド実行は不要。将来OSアダプターが提供する確かな活動区間を、起動時に再生する。現段階ではOS由来の入力を明示的に拒否する。

- processedUntil が二重加算と既処理区間の再生を防ぐ。
- 隙間の時間を勝手に「離れた時間」に変換しない。
- unknown は報酬もペナルティもなし。
- 制作の材料は開始時に予約。完了後は余った時間で探索する。
- 保存に成功してから画面へ反映。保存破損時は上書きせず停止する。
- revisionとWeb Locksで多重更新を防ぐ。Web Locks非対応環境の複数タブ同時更新は保証外。ネイティブではトランザクション保存へ置換する。
- 思い出は直近100件。これは試作の上限で、永続図鑑ではない。

## 本番に進む前の境界

OS入力は順序・重複・競合を正規化する必要がある。同時刻にawayとusageが来る場合の優先ルール、遅延到着、権限変更、日時変更、時差、欠損を実機で検証する。現エンジンの長区間上限480分はデモの暴走防止のみ。同じ時間を分割すると結果が変わるので、本番の集計上限には流用しない。日付・評価単位ごとの上限設計を先に定義する。

ゲームバランスはcatalog.tsに集約。現時点の2時間での大きな変化は比較用。実際の悪化速度や仕事用アプリ除外、睡眠時間の扱いは未確定。
