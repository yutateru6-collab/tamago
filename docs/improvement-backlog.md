# tamago 改善メモ — 優先順位と完了記録

公開アプリ：<https://tamago.itisnowornever271.workers.dev/>

初回監査：2026-09-19（日本時間）。対象コード：[`4a9044b`](https://github.com/yutateru6-collab/tamago/commit/4a9044b82784df8f58fde44c4d847d2011c8f4da)。[画面の証拠・8ステップの評価](audit/2026-09-19/README.md)。

## 率直な評価

**世界観と進行の土台はできている。一方、30分待つ価値を感じる演出、迷わず進める導線、長く残る思い出がまだ弱い。** 現状は「雰囲気のある動く試作」として成立しているが、初めて使う人が翌日も戻りたくなるかは未検証。自動テストの成功を、楽しさや継続率の証明にしてはいけない。

とくに、探索・住処・記録は同じ大きな住処画像が上部を占める。390×844の画面では探索の実行ボタンや制作ボタンが最初の表示に入らない。背景の統一と、毎回同じ大きさで同じ画像を見せることは分けて考える必要がある。

「あつ森などを参考に、基本の住処を保ちながら物が増える」という方向は維持する。家具ごとの追加は実装済み。豪華な一枚絵への切り替えに戻さない。これから必要なのは、追加した物の存在感、使っている実感、次に増やす楽しみである。

## このメモの読み方・更新方法

- **確認**：画面・操作で観察した事実。**コード**：実装で確認した仕様・不足。**仮説**：利用者テストが必要な評価。併記の場合は事実と解釈を本文で分ける。
- **P0**：継続利用を止める重大な障害。今回の範囲では新たなP0は確認していない。完全な安全性を保証する意味ではない。
- **P1**：次の改善で優先。体験の中心、誤操作、記録の保持、利用可能性に関わる。
- **P2**：基本体験を整えた後。**P3**：対象者や公開形態を決めてから検討。
- 工数は相対値：小＝局所変更、中＝複数画面・状態、大＝新しい仕組み・素材制作・実機検証。日数の約束ではない。
- 状態は **未対応 → 対応中 → 修正済み**。調査項目は **検証済み**、採用しない案は **見送り（理由付き）**。一部だけ直した場合は対応中のまま、残りを書く。
- 改善のPRでは該当IDを記載し、**このファイルを同じPRで更新する**。完了時はチェックを `[x]` にし、タイトルを `~~取り消し線~~`、状態を修正済みにする。元の問題・完了条件は消さない。
- 完了欄に **日付・PR/コミット・確認内容・公開反映** を記録する。コード完成だけなら「公開未確認」と書く。画面変更は変更後の画像も残す。仮説の検証だけで実装を修正済みにしない。
- IDは変更・再利用しない。新しい問題は末尾に追加。再発したら同じIDを未対応へ戻して再発日と根拠を追記する。
- このリストは現時点で確認できた範囲の一覧。将来の全不具合を網羅した保証ではない。改善順の提案であり、全機能の一括実装や既存ルール変更への承認を意味しない。
