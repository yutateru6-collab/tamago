# 同じ住処に暮らしを増やす

2026-09-19。以前の「完成数で全景画像を切り替える」方式を置き換える。

## 体験

- 初期は滝・岩・苔・木漏れ日・同じ青い子・灯り一つ。家具は未制作なら表示しない。トロッコや手前の大きな切り株を除き、床と右壁に空間を確保。
- 棚・寝床・庭はそれぞれ制作中の表示→完成。すべて同じ構図と位置で表示する。
- 探索1/2/3回で棚に宝物。2回で「森の小さな手帖」も加わる。これは探索の記念表示であり、消費できる材料の報酬は変更しない。棚がない間は所持状態だけ保ち、棚完成後に自動で飾る。
- 発展と傷みを分ける。花はしおれ、家具はくすむ。大きく傷んでも同じ家具の姿を残す。修繕でその場の物が戻り、完成実績や持ち物は失わない。
- 「住処」の下の「この場所に、少しずつ。」で模様がえ。家具は二つの決まった配置から選択できる。しまうと表示だけが消える。棚の小物は棚と一緒に動く。棚をしまっても小物の獲得は残る。
- ホームは現在の仕事と30分ボタンを中心にし、元気の数値や詳しい説明は開閉式にする。

## 拡張方法

`src/domain/decor.ts` の DECOR に定義を追加する。画像、名前、獲得条件（既存の制作IDまたは探索回数）、表示位置、任意の親家具・傷み用画像を指定する。表示側はカタログを再帰的に描画するので、家具ごとの描画分岐は追加しない。

座標は3:4の背景に対する百分率。子アイテムは親の座標を基準とする。棚の小物を増やすには parent:'shelf' を指定する。キャラの耳・顔・尻尾、滝を隠さない位置を選ぶ。素材は絵柄・光源・遠近感を合わせる。開発者画面の「配置枠を見る」で確認できる。

新しい制作レシピそのものを追加する場合は、既存 catalog.ts の時間・材料定義も必要。現時点でゲーム内の制作は3種類。画像とカタログだけで任意の新しいゲームルールまで実装できる、という意味ではない。

## 保存

通常の `tamago.world.v1` は維持。追加フィールド decor は省略可能で、既存データをそのまま読み込める。配置と収納だけを保存し、完成・探索実績から所有を導出する。旧プレイヤーにも、すでに達成済みの実績に対応した物を表示する。通常の更新は従来と同じ Web Lock と revision 検査を使う。

## 開発者モード

設定→「開発者モードを開く」、または `?dev=1`。

- 通常の記録は localStorage、試作は sessionStorage の `tamago.sandbox.v1`。最初に設定から入る場合は現在の住処をコピー。以後は試作データを再利用。再読み込みで保持され、タブ終了で破棄される。
- 初期、棚50%、棚完成、宝物と手帖、全家具、しおれ、傷み、大きな傷みの8つのプリセット。
- 「30分の休息を完了する」は通常と同じ beginQuiet/completeQuiet。「2時間」も同じ進行エンジンを使用。修繕が先なら制作は進まない。日次上限も有効。
- プリセットは試作用状態の直接指定、イベントは本来の状態遷移。表示で区別する。プリセット選択は試作データだけを置き換える。
- 「この状態でホームを見る」で通常の操作経路も試せる。「通常に戻る」で自分の住処へ戻る。元の保存データは変更しない。

## 画像と動き

`home-base.webp` は imagegen の組み込みツールで home-empty.jpg を参照して制作。原画のキャラ部分は元の workshop-idle.jpg/mp4 を柔らかいマスクで表示し、原画ファイルそのものは変更しない。再生・停止・省モーションを維持。素材の表示や動画再生は報酬を生まない。

画像生成のプロンプト・保存先は art-prompts.md。過去に承認された home-growth-1/2/3.avif は参照用として保持し、自動切替には使わない。

## 受け入れ確認

- 初期に未獲得家具がない。休息2回で棚が完成し、背景を変えず棚だけが増える。
- 探索の結果として宝物・手帖が増え、保存・再読み込みで維持。
- 収納・配置変更で材料や完成実績を変更しない。棚の子アイテムも追従。
- 傷みと修繕でも背景・家具位置・所有を保持。
- 旧データ、保存失敗、キャンセル、二重完了、端末幅320/390/430px、Chromium/WebKitを確認。
- 開発者操作・再読み込み・通常復帰で通常データがバイト単位で変わらない。
- 保護ランタイム28ファイルのハッシュを維持。
